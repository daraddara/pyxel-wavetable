# 音声品質に関する技術課題

## 現状の評価

Pyxel 2.9.9では、生成したwavetableの長さによって実際の発音周波数が変わります。原因はPyxelの整数クロックによる再生方式ですが、その制約を踏まえた既定値・適用音域・説明・検証は本ライブラリの責任です。

現在確認できているのは、通常のToneを生成・登録し、既存のSound/Music/MMLで利用できることです。標準Toneからの置き換え時に、音色だけが変わり、音程や聴感音量が保たれることまでは保証できません。これはライブラリの用途に直接関わる品質課題です。

現時点の正式方針は、整数クロック由来の量子化を仕様上の制約として受け入れ、ライブラリ側で完全なピッチ補正を隠蔽しないことです。`DEFAULT_SIZE=128` を維持し、利用者が使用音域・size・音色再現性・許容できるピッチ誤差の妥協点を選びます。ライブラリは制約を正確に説明し、判断材料を提供します。

## T1：音符が同じでも実ピッチが変わる

生成されたMMLの音符は変わっていなくても、標準Pulse（4点）を128点のPMへ置き換えると、起動時の曲の先頭C5は約523.33Hzから517.87Hzへ変わりました。差は約−18.13セントです。

128点の正弦波でも同じ基本周波数になり、PM固有の倍音による聞こえ方だけではないことを確認しています。誤差の符号・大きさは音程ごとに変わり、高音域では特に大きくなる場合があります。

本ライブラリは使用音域ごとの誤差を提示し、利用者がsizeを判断できる材料を提供します。固定128点・1周期のToneを現在の整数クロック再生へ渡す方式で、全音域のピッチを保証することはできません。sample_bitsやgainの変更では解決せず、固定のdetune補正でも全音程を一括では直せません。これはライブラリ単独で完全解決する対象とはせず、説明した上で受け入れる制約です。

整数クロックへの丸め自体を解消する対応は、再生エンジン側の検討になります。これは本ライブラリの通常Toneを返す責務を越えるため、今回Pyxel本体・Rustは変更しません。

実測値と周波数モデルは [Wavetable長とピッチ誤差](wavetable-pitch.md) に記載しています。

## T2・T3：128点の維持と用途ごとのsize選択

当初のDirect PCM比較の基準音はC3（約130.81Hz）で、128点の誤差は約−1.78セントでした。この結果は再現できています。ただしC5では約−17.88セントとなり、C5〜B5全体の最大絶対誤差は36.66セントでした。

128点を採用した理由には、複雑なPM波形を32/64点で表現した際の粗さを避けることも含まれます。一律に32点へ減らすと、今回のC5〜B5の最大ピッチ誤差は12.02セントまで減りますが、音質上のトレードオフがあり、誤差ゼロにもなりません。

利用者は次の順で判断します。

1. 使用する音域と、必要な波形・PMパラメータを決める。
2. 実際の楽曲で128点を確認し、ピッチ差が気になる場合は64点・32点も試す。
3. ピッチ差と、波形の粗さ・倍音構成の変化を聴き比べる。
4. その用途で許容できる妥協点を選ぶ。

既定sizeの変更は、引数を省略した既存コードのwavetable長と出音を変えるため、互換性上の判断も必要です。今回は128点・8bitを維持します。128点は当初の波形再現性・試聴結果を基にした値で、ピッチ精度の推奨値ではありません。汎用的な自動補正や一律のsize選定を実装せず、用途依存の選択を利用者へ委ねることを正式方針とします。

## T4：生成データの正しさと出音の品質を分けて検証する

Toneの型、mode、整数レンジ、量子化、プリセット値、登録順などのテストが通っても、実際のピッチ精度は保証されません。音声出力を使った検証を別の層として整備する必要があります。

検証項目の候補は以下です。

- 複数音域の全12音で、目標周波数と実測周波数の差を確認する。
- 標準Toneから置き換えたときの差と、12平均律からの差を分ける。
- 単純波形と複雑なPM/倍音波形を分けて評価する。
- 対応Pyxelバージョンを明記し、更新時に音声品質の変化を確認する。
- 波形の粗さなど、周波数測定だけでは判定できない項目は試聴結果として分けて記録する。

今回の測定CSVは基礎データです。音質評価基準や、継続的に実行する品質テストが完成したという位置づけではありません。

## T5：倍音の折り返しはピッチの丸めとは別問題

現在のgeneratorは数式を等間隔でサンプリングし、帯域制限を行いません。wavetableの点数に対して高すぎる倍音や、高音で再生した際に出力サンプルレートで表せない成分は、意図しない周波数成分となる可能性があります。PMではratioとindexを大きくすると評価条件も変わります。

波形を細かくするためにsizeを増やす対応と、クロック丸めを小さくするためにsizeを減らす対応が競合します。ピッチずれ、折り返しによる音質変化、倍音構成による知覚上の音高は、別々に評価する必要があります。

今回の周波数測定は整数クロック由来のピッチ差を検証したもので、この音質問題を定量的に評価したものではありません。

## T6：同じgainでも同じ音量にはならない

現行のnormalizeはピーク基準です。正弦波、矩形波、PMでは実効値と周波数成分が異なるため、同じピーク・同じgainでも聴感音量は変わります。音色比較の印象に音量差が混ざる可能性があります。

既存のgainとnormalizeの意味は維持した上で、音量の比較基準と必要な検証を検討します。聴感音量を一致させたと表現するには別の評価が必要です。

## T7：機能の範囲と品質課題の区別

整数ratioのPMは固定した1周期の音色を作り、Percussionプリセットも静的な周期波形を返します。減衰はPyxel MMLへ任せられますが、それだけでノイズや、時間変化するPM index、打楽器のピッチ変化を再現するものではありません。これらは現在の機能範囲として明示すべき制約です。

整数クロック由来のピッチ誤差を制約として受け入れることは、誤差を補正したことを意味しません。ピッチ精度の保証と受け取られない説明を維持し、利用者が用途に応じて判断できる材料を提供します。

## 確定方針と残る検証課題

1. 通常のToneを返す設計と既定size=128を維持する。
2. ピッチ誤差を隠蔽せず、使用音域・size・許容誤差・音色再現性の選択を利用者へ委ねる。
3. 自動補正、音符ごとのTone切替、独自再生系は追加しない。
4. T4〜T6の品質検証・折り返し・音量差については、追加の評価が必要な事項として区別する。

比較アプリへの追加機能、既定値の変更、独自シーケンサ、Pyxel本体やRustの変更は、今回の課題整理では行いません。
