# Wavetable長とピッチ誤差

`size=128` は当初の波形再現性・試聴結果を基に選んだ初期既定値です。ピッチ精度の推奨値ではなく、すべての音程で標準Toneと同じピッチを保証する値でもありません。`DEFAULT_SIZE=128` / `DEFAULT_SAMPLE_BITS=8` は維持し、利用者が使用音域・音色再現性・許容できるピッチ誤差の妥協点を選ぶ方針とします。ライブラリは自動ピッチ補正を行いません。

## 当初のPoCとの関係

Direct PCMとwavetableを比較した初期PoCの基準周波数は130.81278265Hz、すなわちC3でした。Pyxel Soundの音符文字列では `c1` と指定しており、MMLの `O3 C` に相当します。Sound文字列のオクターブ番号とMMLのO指定は同じ意味ではありません。

このC3では、128点の誤差は約−1.78セントです。一方、gen_bgmで生成した比較用の曲（preset=4 / transp=0 / instr=3 / seed=42）のメロディー先頭はMMLのC5で、同じ128点でも約−17.88セントになります。パラメータが変わったのではなく、鳴らす音程が変わったことでクロックの丸め誤差が大きくなりました。

当初の128点という選択には、32/64点で複雑なPM波形の粗さが目立ち、128点ではDirect PCMとの聴感差が小さかったという試聴上の判断も含まれます。その判断を全音域のピッチ精度へ一般化することはできません。今回、主観的な音質評価は追加していません。

## 実測結果

Pyxel 2.9.9で、標準Pulse（4点）、PMの32/64/128/256点、対照用の正弦波128点を測定しました。PMはratio=3 / index=1.8、生成波形は8bitです。測定値は12平均律の目標周波数に対するセント差です。正は高く、負は低い音を示し、100セントが半音です。

正弦波128点でもPM 128点と同じ基本周波数になりました。今回の差は、PMの倍音構成による聞こえ方だけでは説明できません。

## 原因

このバージョンのPyxelでは、wavetableの次のサンプルへ進む時間を整数クロックへ丸めます。周期のサンプル数をN、目標周波数をf、音声クロックをK=1,789,773Hzとすると、今回の実測は次のモデルと一致しました。

```text
サンプル当たりのクロック数 = max(1, round(K / (N × f)))
実際の周波数 = K / (N × サンプル当たりのクロック数)
```

C5 / 128点では、必要な約26.72クロックが27へ丸められます。標準Pulseは4点なので、より細かい周波数間隔で目標へ近づけます。

長いwavetableや高い音ではサンプル当たりのクロック数が少なくなり、1クロックの違いが大きくなります。ただし誤差の向き・大きさは個々の音程にも依存します。常に低くなるわけでも、個々の音で短い表が必ず良いわけでもありません。sample_bitsは振幅の量子化であり、このクロック丸めを解消しません。

## Practical guidance：sizeと音域の選び方

1. 初めて使う音色は128点を基準にし、実際の楽曲で確認します。低音中心なら誤差が小さい場合がありますが、単音だけで判断せず、使う音域全体を確認してください。
2. 高音でピッチ差が気になる場合は、64点・32点も試します。今回のC5〜B5では最大絶対誤差が128点で36.66セント、64点で19.16セント、32点で12.02セントでした。32点も誤差ゼロではありません。
3. sizeを小さくしたら、ピッチだけでなく音色も聴き比べます。複雑なPMや高次倍音を含む波形では、粗さや倍音構成の変化が生じる可能性があります。PMのratio・indexを変えた場合も確認が必要です。
4. 音色再現性とピッチ差の両方を判断し、その用途のsizeを選びます。「32点なら安全」「128点は使うべきでない」という一律の基準はありません。

同じsize・同じ目標音程で、今回測定したPMと正弦波のクロック由来の基本周波数誤差は一致しました。PMを正弦波へ変更するだけでは、この丸め誤差はなくなりません。ただし波形によって基音が弱い・含まれない・周期内に複数の同一波形を含む場合などは、聴感上の音高や周波数測定の解釈にも注意が必要です。

最適なsizeは音色だけでなく、使用音域と許容誤差によっても変わります。標準Toneとの比較では、同じMML音符でも出音のピッチが一致するとは限らないことを踏まえ、実際の楽曲で選んでください。これらは利用者の選択材料であり、全音域を自動補正する方針ではありません。

## ライブラリとして受け入れる制約

Tone Labの [Pitch Error表示](tone-lab.md#pitch-error音域ごとのピッチ誤差を確認する) は、以下の測定CSVの366条件で確認した整数クロックモデルを使う予測表示です。指定音域でsize別の最大・平均絶対誤差と音符ごとの誤差分布を計算し、再生・録音・FFTを使わず比較できます。測定結果を追加したものでも、ピッチを補正したものでもありません。モデルの適用先はPyxel 2.9.9であり、将来の再生エンジンで同じ結果になる保証はありません。

- 128点・8bitは引き続き波形生成の既定値とします。高次倍音を含む波形を少ない点数へ縮めることには、当初PoCで確認された音質上のトレードオフがあります。
- ピッチ精度が重要な用途では、使用音域で確認してsizeを選ぶ必要があります。今回のC5〜B5では、最大誤差が128点で36.66セント、32点で12.02セントでした。32点も誤差ゼロではありません。
- 固定のdetuneを足すだけでは、音程ごとに向きも異なる誤差を一括で直せません。さらに、整数クロックで表せる周波数そのものが離散的です。
- 静的な128点wavetableを、この再生方式のまま全音域で正確に鳴らす保証はできません。整数クロックへの丸め自体をなくす対応はPyxel側の課題で、本ユーティリティからの本体・Rust変更は行いません。

通常の `pyxel.Tone` を生成する設計を維持し、音符ごとの自動ピッチ補正・Tone切替・自動detune・独自再生系は追加しません。Sound / Music / MML / play / playmはPyxelの標準機能をそのまま使います。

## 測定方法とデータ

全61音（C2〜B6とC7）×6条件、計366点を測定しました。[測定CSV](wavetable-pitch.csv)には周波数・予測値・セント差を収録しています。Python 3.13 / Pyxel 2.9.9、測定日は2026-11-02です。

各Toneをindex 2へ設定し、`T120 V100 Q100 @2 O<octave> L1 <note>` を通常の `Sound.mml()` と `Sound.save()` で1.8秒出力しました。WAVは22050Hz・16bit・monoです。0.2〜1.6秒を切り出し、平均値を引いてHann窓を掛け、524288点のFFTで基本波付近（目標の0.75〜1.25倍）を探索し、ピークの対数振幅を放物線補間しました。分析にはNumPyを一時的に使用し、ライブラリの依存には追加していません。

全366点で、実測値と上記クロックモデルの差は0.06Hz未満でした。生WAV・一時解析コード・ログは配布物に含めず、Pyxel本体・既存PoCは参照のみとしています。結果は当該バージョンでの測定であり、将来のPyxelの挙動を保証するものではありません。
